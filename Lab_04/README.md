# Лабораторна робота №4

## Опис

Рекурсивні алгоритми та мемоізація (варіант 12). Реалізовано чистий рекурсивний quicksort, рекурсивні обходи бінарного дерева, ітеративні BFS/DFS, рекурсивне число Фібоначчі з `lru_cache` і циклічний аналог. Індивідуальне завдання варіанта 12 — довжина найдовшої спільної підпослідовності (LCS) двох рядків: рекурсія з кешуванням станів `(i, j)`, наївна версія для короткого порівняння та ітеративна табуляція.

## Рекурсія та результати

У quicksort база — список із нуля або одного елемента; крок — поділ відносно випадкового опорного значення на менші, рівні й більші елементи. Для обходу дерева база — відсутній вузол, а рекурсивний крок відвідує його дітей у потрібному порядку. У LCS база досягається, коли один індекс вийшов за межі рядка; при однакових символах індекси рухаються разом, інакше береться максимум двох підзадач. `lru_cache` зберігає відповідь для кожної пари індексів.

Кеш Fibonacci доступний через `fib.cache_info()` і `fib.cache_clear()`. Для LCS ці операції надані через `lcs_cache_info()` та `lcs_cache_clear()`. Порівняння часу запускається окремо командою `python benchmark.py`. У поточному запуску найкращий час для LCS на рядках довжини 12 становив 0.000767 с без кешу, 0.000028 с із кешем і 0.000019 с для ітеративної табуляції. Для Fibonacci при `n=30` отримано 0.000006 с із кешем та 0.000001 с ітеративно. Час залежить від середовища виконання.

У CPython стандартне обмеження рекурсії зазвичай становить близько 1000 кадрів і читається через `sys.getrecursionlimit()`. Автоматичної оптимізації хвостових викликів (TCO) немає, тому рекурсивний алгоритм може завершитися `RecursionError` на глибоких даних навіть тоді, коли кожен крок є хвостовим. Ітеративні обходи дерева та версія LCS без рекурсії не залежать від глибини Python-стеку й безпечніші для глибоких структур або довгих рядків.
